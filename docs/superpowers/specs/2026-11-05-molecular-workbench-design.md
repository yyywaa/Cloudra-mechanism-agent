# 独立分子工作台与化学对象产物视图

日期：2026-11-05。状态：用户已于 2026-11-05 确认“好，按这个实现”，进入实施。

## 目的与已确认的方向

把当前服务于 DAG 的分子查看窗口独立为项目工具。用户通过前端控制台直接参与研究：查看、创建和编辑分子，设置计算条件，生成输入，以及把保存后的结果交给 Agent 继续使用。用户不需要使用终端或填写工具 JSON。

“把用户当成一个 Agent”指用户与 Agent 都是项目参与者，操作同一批研究对象，产生可追溯的项目文件和事件。它不要求创建一个替用户推理的虚拟 Agent，也不要求把现有内部工具参数直接做成表单。

用户已明确：

- 分子窗口独立于 DAG；快捷键、分子实例、计算结果、产物文件均可打开。
- 控制台支持新建结构、从输出解析结构、生成输入文件。
- 默认打开最新解析帧，同时保留每一帧并可回看。
- 优化显示结构、能量曲线、RMS 力曲线；频率显示真实模式动画；IRC 显示每个点；扫描显示扫描曲线。支持 CSV 导出。
- 记录原子点选顺序：两原子定义距离，三原子定义键角，四原子定义二面角。
- 同一组点选提供“调整结构数值”和“定义扫描／冻结”两个动作；确认的设置可在分子画面或边栏显示。
- 几何修改默认固定前面一侧，移动最后选中原子所在的基团；允许切换固定侧。
- 支持基于 SMILES 的基团替换、跨项目共享的历史 SMILES 基团库、镜像，以及加键和减键；基团库按本项目优先及使用频率排序。
- 文件管理与几何数据分开；结构记录保存来源、编号、几何关系与已决定的计算设置。
- 多个扫描坐标默认作为势能面扫描。
- 用户点击保存，文件进入项目 `.cloudra`，并通过事件提醒 Agent 修改从何而来、保存在哪里。
- 产物视图与 DAG 关联，用户能看出产物属于哪个化学对象、做了什么计算。
- 原产物页与 DAG 页合并为一个控制台页面入口。standard 模式在这里展示结构、计算和产物，DAG 模式在同页加入机理图与关联定位。
- 原来固定在 DAG 页内的大分子查看窗口取消常驻展示；页面提供小型结构预览，点击或快捷键呼出完整独立分子窗口。

## 实现方式的选择

采用用户指定的独立分子窗口，以及合并后的 DAG／产物页面：机理图、对象产物和项目文件都打开同一个分子工具。普通项目也能使用，DAG 仅提供已有的化学归属和证据上下文。

讨论中没有选择重做完整前端。以下两种做法不作为本次方向：

- 只继续扩展 DAG 内部查看器：仍会让普通结构、日志和手工建模依赖 DAG。
- 另建独立科学平台及对象登记体系：重复项目、文件、分子、计算和证据的现有职责。

查看与绘制引擎的具体依赖、窗口组件和样式由实施者选择，需支持本地打包并复用项目现有 React/TypeScript 技术栈。选择渲染库不等于已经获得三维编辑能力，必须分别验证点选、几何编辑和真实动画。

## 前端操作

### 打开与窗口

工作台是项目级可呼出的窗口，可展开以便查看曲线和编辑参数。默认快捷键暂由实施者选择，并显示在入口旁；不占用输入框常用编辑快捷键。

取消 DAG 内原来常驻的大分子查看区域。合并后的页面只保留用于辨认对象的小型结构预览；完整三维查看、曲线、播放和编辑都在独立窗口中进行，不要求用户始终打开该窗口。

打开入口携带已有上下文：结构或文件、对应计算、DAG 物种或反应步骤，以及指定帧。没有指定帧时打开该计算最新可解析的一帧，不能把它自动称为“收敛结果”。

窗口提供结构来源、分子画面、帧播放控件、曲线、几何／计算设置边栏。打开其他文件或切换曲线只更换查看内容；未保存编辑稿需要保留或让用户明确处置。

### 点选、测量与内坐标

点选顺序属于当前选择；原子实际编号和第几个被选中须分别标识。

| 有序选择 | 坐标含义 | 单位 |
| --- | --- | --- |
| A → B | 原子间距离，不要求已经成键 | Å |
| A → B → C | 以 B 为顶点的键角 | ° |
| A → B → C → D | 围绕 B—C 的二面角 | ° |

取消选择、重新点选与清空选择都应直接可操作。窗口内编号稳定；后端编号转换由程序根据具体结构与引擎处理，用户无须手动转换。

两个动作：

1. **调整结构数值**：输入目标数值，预览移动部分，确认修改进入编辑稿。默认固定前面一侧，移动末端原子所在基团；“切换固定侧”反转移动部分。距离为 A/B 两侧，角度为 B 顶点的 A/C 两侧，二面角为 B—C 轴两侧。不能唯一划分时，让用户指定移动原子，不能静默改动整个分子。
2. **定义扫描／冻结**：冻结使用用户确认的目标几何；扫描填写起止值与步数，步长如在界面提供则与步数同步。确认后进入当前编辑稿的计算设置。多个扫描坐标按用户要求进入势能面扫描，不能把多坐标扫描偷偷改成同步改变坐标的一条路径。

确认的坐标条目显示有序原子、类型、当前测量值、扫描／冻结设置，支持编辑、删除和画面标注显隐。查看其他帧时，当前测量值随帧变化，已确认的扫描目标和冻结定义保持不变；确认的冻结目标需绑定定义时的几何，生成输入时必须正确表达，不能仅在新结构当前值处冻结。

### 连接关系、基团与镜像

- 支持在两个选定原子之间新增／删除键，并调整键级。分子图、显示和保存内容一起更新；XYZ 只作为坐标导出，不能用它保存完整分子状态。
- 基团替换使用 SMILES。用户可输入新基团，也可从历史库选择。库项至少能显示名称或 SMILES、结构预览和连接位置；可搜索、复用和删除。
- 库记录确认使用过的基团，预览或输入失败不产生历史条目。替换时先标明保留侧和将被替换的基团，再展示新基团的连接结果。
- SMILES 未明确连接位置时，通过图形选择连接位置。程序再转换为现有几何操作所需的连接点表示。
- 历史库保存可复用的基团图、连接位置与局部几何；安装到不同母体时重新摆放。不能把第一次替换后的整个分子或绝对坐标作为基团模板。
- 历史库跨项目共享，作为用户的常用基团库。具体结构、计算设置和编辑来源仍保存在各项目 `.cloudra` 中。
- 排序先将本项目使用过的基团放在前面，各组内按累计确认使用次数从高到低排列；仅预览不增加使用次数。本项目优先只影响排序，不复制一份项目基团库，不引入权重或评分配置。
- 镜像提供目标和镜面选择，并预览结果；整分子镜像与已有局部手性翻转须区分。
- 几何、键和基团操作使用同一编辑稿和撤销记录。几何整理／优化是显式操作，不能在普通编辑时无提示地重新优化整个分子。
- 替换删除了某条扫描／冻结设置引用的原子时，指出受影响条目供用户修订，不能将原编号悄悄指向另一原子。

## 计算过程与图形联动

解析在后端复用现有原生解析器；前端不再写一套 Gaussian／ORCA 日志解析。每一条曲线都与对应结构记录和实际计算点关联。

| 计算／数据 | 展示与保留 |
| --- | --- |
| 几何优化 | 每个实际输出的几何优化步、该步能量、可取得的 RMS 力及单位；曲线点与几何帧双向选中 |
| 频率 | 实际频率及对应的原子位移，选择模式播放；示意振动不作为计算模式使用 |
| IRC | 原生输出的点、方向／路径信息、反应坐标、能量及对应结构；不把内层 SCF 或校正迭代冒充 IRC 点 |
| 一维扫描 | 扫描坐标、该点结果、对应结构和能量曲线；原生格式能区分时可展开该点的优化过程 |
| 多维扫描 | 各扫描坐标与采样点结构／能量；二维结果可用网格查看，更高维通过固定其余坐标查看切片 |
| 已有力场轨迹 | 复用已保存的逐迭代结构、能量和梯度；明确其力场来源和单位 |

这里的“保留所有帧”指保留计算软件实际输出的相关几何帧，不插值补造遗漏的计算事实。能量按真实值显示，不强制呈单调下降。RMS 力与最大力／最大梯度是不同量，缺哪个就保留缺失，不能互相冒充。

CSV 导出包含点／帧标识、路径或扫描坐标、可用的能量和力指标及单位，能对应回结构。轨迹从磁盘按需读取，不能把千上万帧始终塞进前端或一个巨大的内存对象。

本次首先覆盖现有分子计算主线 Gaussian／ORCA，以及仓库已有力场轨迹和可用的结构文件。具体原生事实不齐全时显示实际可用内容；不能因为某后端缺失一项而限制另一后端。

## 文件、结构、计算的关系

沿用现有分子、轨迹、产物、作业与 DAG 引用，把查看需要的信息串起来。只区分三种职责，不建设新的通用存储框架：

1. **来源文件**：原输入、输出、轨迹边文件、产物快照等，保留原文及引用。
2. **计算记录**：关联来源文件、实际参数、帧序列、曲线、模式和结果。重复解析同一来源更新其派生视图，不凭空制造一批同名化学物种；文件有新增内容时接入新增可解析事实。
3. **结构及编辑稿**：实际分子图、精确坐标、原子身份／编号、来源计算与帧，以及准备给下一次计算使用的设置。由某帧开始编辑时，形成派生稿，原计算帧保持原样。

已执行计算参数属于该次计算；下一次计算设置属于当前编辑稿。编辑可以继承用户已决定的参数，但不能把旧结构的能量、频率或 TS／IRC 验证结论当作新结构的结果。

保存应包含程序可重新打开的完整分子状态、来源和计算设置；MOL／SDF／XYZ、原生计算输入与 CSV 是相应用途的文件产物。不要把 XYZ 当作键、原子身份和计算设置的唯一真相。

内部编号、摘要、并发控制和证据绑定由程序维护。用户与 Agent 只需要具体结构、科学输入和操作意图。

## 产物栏与 DAG 的整合

### 同一个页面入口

删除原先“DAG 页”和“产物页”两个分开的导航入口，合并为同一页面；最终标题由实施者选择。结构与计算结果使用同一套展示与打开行为，不分别维护 standard 和 DAG 两套产物页。

- **standard 模式**：直接展示项目结构、计算记录和产物；有小型分子结构预览，不展示无用的空 DAG 占位，也不要求先关联化学对象才能使用。
- **DAG 模式**：同页展示机理图和结构／计算结果。选中物种或反应步骤可以定位或筛选已有明确关联的内容，结果卡片可定位回对应图对象。
- **独立分子工具**：点击分子预览、可查看的结构／计算产物或快捷键呼出。原 DAG 大分子窗口不再固定嵌在页面里。

预览只用于识别当前结构，显示其来源。存在实际结构时使用对应结构；只有 SMILES 时可以显示二维结构图，不能悄悄生成三维坐标当作原计算结构。没有可解析分子的报告等产物正常展示其他摘要，不伪造分子预览。小预览与完整窗口读取相同的结构引用，不另存一份编辑状态。

### 化学关联与来源

产物视图按已有明确关联展示“化学对象 → 计算与结果”；没有化学关联的内容按计算记录或来源文件组织。文件管理、计算来源和化学对象关联分别表达，不把它们合并为一个自动推断的“归属”。不另建第二套化学对象登记系统。

归属采用保守规则：

- 程序已有的作业、输入、输出、来源帧、生成操作等记录，可以直接展示为来源事实。
- 物种／反应步骤关联只展示已经明确记录的 DAG 引用，或由用户、具有相应权限的 Agent 明确建立的关联；沿用现有图修改入口，不新增人工审批层。
- 不根据文件名、文件夹、SMILES 相似度、打开时选中的 DAG 节点或当前聊天对象自动判定化学归属。
- 一次计算或一份文件可能涉及多个对象。仅有关联到作业的记录时，不能顺推该作业的全部产物、所有帧和后续派生结构都属于同一个物种／步骤；只呈现实际记录的关联范围。
- 一份产物允许与多个对象明确关联，文件保持一份；不强制选唯一所有者。
- 关联不明时显示“未关联化学对象”，同时保留计算类型、实际状态和来源等可读信息。归属明确与否不影响打开、查看、编辑或保存。
- 从已关联结果开始编辑的新结构，只自动保留“派生自哪个文件／哪一帧”。新结构的化学对象关联另行明确，不默认继承父结构关联，不改写原关联。
- 化学关联与科学证据分别展示。建立关联本身不证明结构身份、优化收敛、TS 或 IRC 验收成立。

对象下能区分：输入结构、编辑稿、优化结果、频率、IRC、扫描、报告，以及可展开的原始文件。卡片显示对象名称、计算类型、实际状态和结果摘要；点击打开同一个分子工作台并定位对应计算或帧。

DAG 点击物种或反应步骤，能够定位其明确关联的计算／结果；从产物结果也能回到记录中关联的 DAG 对象。输入、日志、轨迹、曲线可以按同一次计算组织；这种计算分组不扩大化学关联的范围。

未绑定 DAG 的结构和计算仍能显示、编辑和保存；明确呈现其未关联状态，并允许用户关联现有物种或反应步骤。不能仅根据文件名猜测化学归属，也不为了查看一个文件而要求先建 DAG。

## 保存与协作

几何／参数确认保存在当前编辑稿；项目级“保存”将完整内容与所需文件写入项目 `.cloudra`，登记现有产物记录，并产生可追溯的人工编辑记录。

保存成功后，复用现有持久消息通路通知项目主 Agent。通知包含来源文件、来源帧、新保存路径、用户修改与扫描／冻结设置摘要；具体编号与来源由程序附带。不能让 Agent 猜测新文件在哪里，也不能在文件尚未写成功时报告保存成功。

编辑结构、生成输入、保存、提交计算是界面中明确的动作。保存不会自行启动量化计算；若提供直接提交，必须是用户单独点击提交，使用现有计算队列与原有科学参数要求。

人工编辑不会自动替换 DAG 已验收的证据。新候选或新输入经明确操作可以关联到研究对象，随后根据真实计算结果更新研究结论；仅保存编辑稿不建立新的化学归属。

## 完成后用户应能走通的操作

- 无 DAG 的项目从控制台新建／导入结构，呼出工作台，编辑后保存，Agent 能知道来源并读取新文件。
- standard 与 DAG 使用同一个合并页面；standard 可直接查看产物和小型结构预览，DAG 同页联动明确关联的计算结果，页面不再常驻大型分子查看器。
- 从 DAG 物种／反应步骤打开对应计算真实结构，再从产物回到该化学对象。
- 打开优化输出默认看最新帧，曲线点选与帧同步，并导出可对应结构的 CSV。
- Gaussian／ORCA 可用的真实模式、IRC 和扫描数据通过同一个窗口查看；缺失事实保持缺失。
- 按顺序选择原子，调整距离／角度／二面角，切换固定侧，撤销，并创建冻结／扫描设置。
- 新增／删除键、调整键级，替换并复用历史 SMILES 基团；重新打开保存结果时连接关系与设置仍在。
- 原始计算、结构帧与科学证据不会被编辑稿覆盖；查看动作不产生伪计算结果。

## 本稿留给实施者的选择

- 三维引擎、组件组织、窗口布局、快捷键和样式。
- 项目 `.cloudra` 内的具体目录及文件名；沿用现有产物和轨迹约定。
- 复用现有模型时需要补充的最小字段、共享解析实现和 API；内部协议不暴露给用户或 LLM。
- 相关模块的行为测试、前端交互测试和 Gaussian／ORCA fixture 回放；本地不跑全套。
