# Cloudra 构象选择与计算预算补充设计

日期：2026-10-01。依据：本次讨论中用户同意的产品目标与设计取舍；本文件记录该共识及第一版实现边界。

## 1. 产品目标

Cloudra 的目标包含可负担性：在有限计算预算下获得可信结果，并让每次新计算具有明确用途。AI 根据反应意图、结构差异、已有计算与失败证据选择下一步；程序负责几何测量、身份检查、去重、预算账本和幂等执行。AI 的成本收益必须与简单规则基线对照，不能假定引入模型就节省算力。

保留生成过的候选及其来源，不宣称覆盖全部构象空间。默认自动化选择代表按需执行；需要化学判断时可以在首次计算前介入，失败后也可以回退到未尝试区域或申请补充采样。

## 2. 与已有 TS 设计的关系

本设计补充 `2026-10-01-ts-prepare-autode-design.md`，执行拆分见同日构象计划。

- 原设计的 xTB 优先规定适用于**已经决定需要优化**的候选；不意味着所有生成候选都必须立即逐个 xTB 或高级别优化。本设计决定“计算谁、何时计算”，原设计决定“已选任务怎样可靠执行”。
- 先保存候选，之后再生成面向展示或兼容旧接口的筛选视图；能量窗口不能删除档案中的高能结构区域。
- 候选数量和新增作业预算属于搜索资源分配，不转化为引擎 maxiter、路径 nrun 或计算 deadline。预算不足只阻止新提交，不取消已接受或运行中的任务。
- 既定方法、溶剂、电荷、自旋、参考态、频率/IRC/端点身份验收保持；预算不足输出未完成，不能降低验证标准。
- 同一流程恢复，保留有效上游及独立分支；候选切换重做其实际依赖，不固定回到 build。
- 本计划不实施 CRF/RFO 移植、通用计算寿命改造或新的 TS 自动推进器。这些由原计划提供；缺少基础能力时集成不得标为完成。

## 3. 候选档案与结构区域

每个生成候选拥有稳定 ID、物种身份、完整原子身份、片段身份、不可变坐标引用、生成方法/参数/种子和资格检查。身份不同（连通性、立体化学、质子化或自旋不同）的候选分开管理，不用普通构象聚类掩盖身份变化。

优化结果创建子候选，记录 parent ID、作业 ID、方法指纹、真实收敛状态和优化前后区域。保留失败与无能量候选；无能量、无收敛、被拒绝不能写成零能量或成功。两个子候选合并到同一区域时，原父候选与已完成作业仍然保存。

分区首先依据显式描述符：关键二面角、距离、角度、环构象及组分相对取向。反应活性原子及邻域、已声明约束优先；第一版自动补充分子图中可旋转键对应的确定性二面角。对称等价与编号变化通过稳定原子身份/图对应处理，不能把镜像立体身份合并。未支持的环或取向描述标为缺失，不编造语义。

第一版使用可配置的归一化结构距离和确定性代表聚类，不枚举所有内坐标区间的笛卡尔积。二面角距离使用周期最短差；默认容差暂定二面角 30°、普通角度 15°、距离 0.5 Å，明确为待校准的工程初值，不是科学最优值。声明距离窗口的满足情况另作资格证据，不被这些聚类容差放宽。默认均衡使用所选描述符，后续反应特定权重显式记录。

按稳定 ID 顺序建区：候选与某代表的最大归一化差不超过 1 才归入该区；否则建新区。选择最近代表，平局按 ID；区域 ID 由分区版本和代表 ID 派生。新增候选不得悄悄改写旧分区，重分区建立新版本及映射。缺失关键描述符时不自动合并。全局 RMSD 用于区域内近重复标注，不能单独否定反应局部结构差异。

能量不决定结构区域 ID。能量比较要求方法、能量定义、溶剂、电荷、自旋、身份及参考约定一致；不同方法分列、缺失保留。区域间相对能量只在可比较集合内产生，不将 xTB/MMFF/UFF 混排。能量、预组织和空间覆盖共同用于优先级。

## 4. AI 可用证据

程序产生结构化卡片：区域/候选 ID、原子身份对应的关键内坐标及单位、资格证据、同方法能量、已有作业/失败、成本估计及来源、未尝试选项、缺失信息。简短文本标签必须可追溯到数值规则；不得从“gauche”“近距离”直接断言低势垒或正确机理。

候选卡片可以按需分页；摘要始终包含总区域数、被省略区域 ID/读取位置，不能只展示能量最低区域。已有集合不足时支持明确的补充采样请求。

AI 输出结构化选择及理由/证据引用。允许动作：选择既有候选、精修代表、请求补充采样、提出声明调整、停止并报告不确定性。AI 不生成任意 shell、不改变科学方法、不提升用户硬预算、不提交作业；决策通过校验后由系统执行。

## 5. 默认策略与决策节点

默认优先满足声明的几何/身份资格；首先挑选未尝试的结构区域，其次在可比较能量集合内选较低能代表；无可比能量时用预组织偏差和稳定 ID 排序，不伪造统一能量排名。失败后避免重做完全相同输入，但基础设施故障可复用或恢复原作业，不能自动视为化学失败。

首次存在不同反应面或质子转移假设、科学声明有歧义、反应特定优先级无法由规则判断时，输出需要化学判断的 blocked 卡片。常规成功阶段不唤醒 AI。候选失败时区分几何资格失败、路径/TS失败、非收敛、错误反应方向、端点身份不匹配和基础设施错误；提供证据，不未经证明归因于某个二面角。

第一版不自动搜索 TS 外围构象；它是成功找到 TS 后的独立可选工作，不与多反应物种子搜索混淆。也不一次性叠加全部多组分采样算法：保留现有定向采样，按缺口补充可复现的独立片段取向采样。

## 6. 预算与持久化

预算来自用户显式配置或透明的产品套餐配置，记录来源。未配置不暗设“最多几个 TS”或升级次数。第一版支持新增逻辑计算任务数上限和可选预计 CPU 小时上限；模型调用次数/实际 token 单列，若有显式上限一并执行。货币成本仅在有定价来源时提供，不凭空换算。

优化、路径、梯度子任务、TS、频率、IRC、端点任务都必须计入所配置的预算作用域。CPU 估计不确定性可见；配置 CPU 上限而任务没有有效估计时 blocked 请求估计或明确调整，不能按零成本入账。实际耗时与估计分别记录；超出估计不杀作业，但影响后续可用额度。

复用现有 compute.db，原子预留预算与唯一决策动作，绑定作业时消费预留；重复动作/完成事件不重复收费。已接受 READY 任务也占额度。失败作业保留实际消耗；未接受动作的预留可释放，释放必须核对没有绑定作业。重启 reconcile 核对预留与作业，不凭租约过期回收仍有活跃作业的额度。

提交选定候选前列出必要验证链的后续动作及估计。显式预算明显不足时 blocked；预留验证链可降低半途耗尽概率，但未知数值优化步数不能保证最终费用。运行中预算超支时不扩大搜索，保留已获得证据并如实标注未完成。

## 7. 验收与验证边界

第一阶段仅运行离线几何、档案、事务和固定事件 fixture 测试，不在 Mac 跑 QM、不部署、不停止现有计算、不新增依赖。合成 fixture 只验证机制，不能报告科学成功率或 AI 省算力效果。

之后用明确来源、同方法/节点/预算/验收标准的远端案例比较：当前最低能代表策略、结构分区确定性策略、分区加 AI 策略。报告可信完成率、任务数、实际 CPU 小时、模型 token/费用、失败作业成本、重复计算、未完成原因和区域覆盖。固定已有事件的回放只衡量决策行为；没有测量的分支不编造结果。真实远端对照与上线单独安排，先以 opt-in 接入。

## 8. 实施期间新增方向：统计检验启发划区（2026-10-01）

用户进一步明确：希望统计检验直接参与是否拆区、选择内坐标和确定边界，而不只是给固定分区追加显著性标签。现有固定容差分区只作为可复现的对照策略，不能描述成最终统计划区方案。

关键内坐标分两层：程序提出可测量候选（明确的成断键距离、声明窗口、图上可旋转键），再依据当前反应的进攻方向、反应面、质子转移、可达性与环构象选定关键项，记录原子身份、来源及理由。不能因为坐标的统计差异大就认定它化学关键；首版允许 coordinate_keys/coordinate_reasons 显式筛选，并展示默认描述符的图结构/反应声明来源；图规则提出的可旋转键不自动变成化学上关键的坐标。

预期统计流程：反应语义提出候选描述符 → 当前集合寻找候选拆分 → 衡量组间差异与组内采样波动 → 给出拆分建议与不确定性 → AI/默认策略保留、合并或补充采样。统计建议不删除候选，不证明反应路径/势垒，也不取代身份检查。

首版范围已在下文确定，推断限制保持：当前构象并非已证明独立同分布的样本；同一批数据用于选坐标、找切点和检验会产生选择偏差。普通两样本检验或挑最小 p 值不可直接用于决定拆区；简单留出数据也不自动消除按同一待检坐标分组的截断效应。需要记录独立采样批次、周期变量表示、探索性检验边界，以及对整个坐标/切点搜索过程的校正。

参考：Gao/Bien/Witten，Selective Inference for Hierarchical Clustering，https://arxiv.org/abs/2012.02936；其选择性推断有特定算法/分布假设，不能直接移植为当前贪心构象分区的有效 p 值。此研究方向先做离线合成数据校准，不在方法、抽样模型、显著性与效应量规则未达成一致前启用硬拆分判据。


### 已接受的首版统计范围

用户接受探索性评分与稳定性：重采样重复整个坐标/切点搜索，以拟合单峰参考衡量拆分证据，保留效应量、周期表示、抽样假设和不确定性。不用普通 p<0.05 做硬拆区规则，不声称样本独立同分布。coordinate_keys/coordinate_reasons 由反应语义明确选择；能量轴须完整可比且收敛。proposal_indices/decision_id/reason 显式接受，additional_candidate_ids 支持优化子候选，旧成员/谱系保留。生产阈值仍需合成校准与用户确认，本次不默认设置。
