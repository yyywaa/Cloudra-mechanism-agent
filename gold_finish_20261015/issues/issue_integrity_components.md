## 现象（读码 + 实例）
`cloudra/benchmark/integrity.py` 的 `_species_file_qualities` 规则要求：证据文件里 `smiles:` 注释的**组分个数**必须与图节点 smiles 的**组分个数**相等，否则该节点直接跳过（兜底 `_component_union_coverage` 也要求逐组分个数相等）→ 该节点未绑定 → **该边能垒"不可从证据推导"（等于该步拿不到分）**。

实例（NI5，水溶液亚胺形成，normal 档）：
- 题面是 **schematic SMILES**（明确声明"接力水与酸不画进反应物侧"），参考图节点 `NI5_R` = `C=O.CN`（**2 组分**）。
- 但按条件（pH 4–6 水溶液、机理含一分子接力水）建模，真实计算体系必须含 **1 个显式接力水** → 解题 agent 的证据注释自然写成 `C=O.CN.O`（**3 组分**）。
- 若 agent 照抄参考图的裸 SMILES 作为图节点，则**即使 E1（C–N 加成）算对也拿不到分**。

## 为什么值得 triage
- 这不是某个 agent 的失误，而是**题面/参考图与"必须补显式溶剂分子"的建模要求之间的口径缝隙**：schematic SMILES 允许不画水，但证据侧的组分计数规则又强制两边组分个数一致。
- 受影响面可能不止 NI5：任何"题面 schematic、但机理上需要显式桥水/酸/对离子"的条目（本战役里的 NI5/NY3/NR1/HL1 都有类似张力，NY3 还涉及 Na⁺ 是否画进 SMILES）。

## 可能的方向（供裁定，不自行实施）
1. 参考图节点按真实建模口径补上必须显式的分子（例：NI5_R → `C=O.CN.O`），或在题源声明"允许证据侧组分多于参考节点"；
2. 或让组分计数规则在"参考节点是 schematic、且题面明确声明省略"时放宽为"子集覆盖 + 题面允许的额外组分白名单"；
3. 或在生成器侧为这类题写入 `smiles_schematic: true` 并让 integrity 规则据此切换口径。
