## 二、GraphRAG 在 Cloudra 里的定位与初衷

大语言模型本身通过海量预训练已经记住了很多通用的有机化学八股文，但在面对真实的量子化学计算时，普遍存在一个致命短板：**它只知道什么是理论上正确的，但不知道计算失败了该怎么救。**

在真实的算化研究中，90% 的时间往往花在试错与报错排查上——例如：
- 过渡态优化收敛但出现了多个虚频（`n_imag > 1`）该怎么消除？
- SCF 能量震荡不收敛时该选什么算法？
- IRC 放坡两头滑向同一个极小点时怎么重新微扰？
- 开壳层自旋污染 `<S²>` 严重超标时如何破缺自旋或判断是否需要拒答？
- 计算 HFIP 等特殊强氢键溶剂时，什么时候只套 SMD 连续介质模型会翻车、必须加显式溶剂团簇？

**我们的核心初衷**：把**计算化学公社（Sobereva 老师的博客教程与论坛精华帖）**以及权威方法学文献中的宝贵实战经验蒸馏出来，作为 Agent 的“外挂排错锦囊库”（L0 级实战知识）。当 Agent 在计算中遇到报错或做决策时，能够直接检索到可执行的高质量建议。

**请注意：图谱完全不需要拘泥于任何死板的节点类型或固定的数据格式！**

我们的核心原则只有一条：**安放尽可能多的高密度、高质量的有效信息。**

图谱的结构和分类维度完全由师兄来决定，可以根据你对计算化学公社文章的理解自由发挥，例如：
- 可以按**“报错现象与排查路线”**组织（遇到什么报错 → 先看什么指标 → 推荐改什么关键词/坐标 → 兜底方案）；
- 可以按**“计算方法与参数选型指南”**组织（某类反应/元素体系 → 推荐什么泛函与基组搭配 → 溶剂效应与色散校正注意事项）；
- 可以按**“软件与工具实战技巧”**组织（Gaussian / ORCA / Multiwfn / xTB 的避坑经验与黑魔法）；
- 或者将上述维度混合打通，形成一张丰富的实战网络。

## 四、我们的初步构思（仅供参考，不作为约束）

我们在讨论时曾构思过一种适合算化排错的**有向决策图（Decision DAG）**形态，这里写出来仅供师兄参考和启发灵感：

### 1. 结构构想（仅供参考）
- **现象（Symptom）**：如“TS 优化出现多个虚频”；
- **诊断判据（Diagnostic）**：如“检查次级虚频模态是否为侧链旋转、振动频率是否 < 50 cm⁻¹”；
- **解决动作（Mitigation）**：如“沿该振动模态位移 0.1 Å 后重新 opt(ts,calcfc)”；
- **兜底方案（Fallback）**：如“尝试两次仍未解决，提升基组精度重算力常数”。

### 2. 检索与呈现形式（仅供参考）
当 Agent 遇到问题检索时，系统找到对应节点并顺着关系展开 1–2 步，最终以清晰的树状导图呈现在模型的上下文（Context）中：

```text
[公社排错图谱：TS 多虚频处置路径]
当前故障: 过渡态优化出现多个虚频 (n_imag > 1)
├─ 诊断步骤 1: 检查次级虚频 (freq_2) 的振动模态与大小
│  ├─ 分支 A (次级虚频 < 50 cm⁻¹ 且为无关侧链/甲基旋转)
│  │  └─ 推荐动作: 沿该次级模态微移构型 0.1 Å -> 重新执行 opt(ts,calcfc)
│  └─ 分支 B (两虚频数值相当，且均涉及反应主骨架成键断键)
│     ├─ 根因诊断: 初猜构型很可能落入了高对称性的二阶鞍点
│     └─ 推荐动作: 手动扭曲二面角 5-10° 打破对称性 -> 重新提交 QST2/TS 搜索
└─ 兜底策略: 若尝试 2 次后仍存在多虚频 -> 建议改用更高精度泛函重新生成初始 Hessian
```

师兄**完全不需要编写任何 Python 代码**！推荐利用 ChatGPT / Claude 等大模型协助完成文章的批量提取：

1. **挑选文章**：从计算化学公社（sobereva.com 或 keinsci.com 论坛精华区）挑选高质量教程（如过渡态寻找、IRC 技巧、泛函基组选择、溶剂效应、开壳层处理、Multiwfn 教程等）；

3. **人工化学复核**：师兄凭借自己的计算化学专业背景扫一眼，修正 AI 可能曲解的专业术语或参数；
4. **保存交付**：存成普通的 `.json`、`.yaml` 或 `.md` 文件，放到仓库的 `data/knowledge/` 目录下即可。底层的数据加载和接口对接由代码端全自动处理。
