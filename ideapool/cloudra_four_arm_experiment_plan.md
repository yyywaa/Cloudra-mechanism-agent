## 一、论文要回答什么

面向 JCTC / JCIM 的 Agent 系统论文，核心问题是：**科学校验、DAG 证据组织、化学算法与有操作价值的错误反馈，如何共同增强 Agent 完成反应机理研究的能力与可靠性？** 这是待实验检验的主张，不提前写成效果结论，也不以某一个底层算法必须首创为前提。

化学算法提供实际的结构构建、构象处理、路径探索、过渡态与相关计算能力，是系统能力的实质；DAG 与科学校验使假设、计算、证据和交付要求形成可追溯关系，直接参与工作推进；诊断反馈则帮助 Agent 识别失败并选择下一步。DAG 是重要机制，但不能作为整篇文章唯一的 novelty，也不能用编排说明代替化学能力展示。

正文围绕具体任务展示完整过程：提出机理假设并建 DAG → 选择工具完成计算 → 将证据与待验证主张绑定 → 指明哪一层发现并拦下失败 → Agent 根据反馈恢复、修正或如实停止。需要既展示成功，也展示失败、有效 partial 和方法边界，不能只展示漂亮的终图。

近期主要任务是把下述四组实验干净地跑通。暂不铺开逐个化学算法的全量消融，也不采用在同一条运行轨迹中临时分叉、替换反馈后继续跑的方案。

## 二、四组实验及可解释范围

| 组别 | 分支 | 科学校验工具 | Supervisor / 科学结算强拦截 | 错误反馈 |
| --- | --- | --- | --- | --- |
| A 完整版 | `benchmark/arm-guided` | 保留 | 保留 | 原完整诊断与引导 |
| B 无强制干预版 | `benchmark/arm-record` | 保留，可自主调用 | 去掉 Supervisor 拦截，不主动因科学校验强行阻止结算 | 除实验因素外与 A 对齐 |
| C 无校验工具版 | `benchmark/arm-standard` | 在 B 基础上移除指定科学校验工具 | 同 B | 除实验因素外与 B 对齐 |
| D 简略报错完整版 | `benchmark/arm-guided-brief-errors` | 同 A | 同 A | 只简化错误解释与修复引导 |

表内是实验目标，不是对当前实现已经满足条件的断言。分支名或 `mode` 标签可能与真实行为错位，必须以实际注册工具、角色启动、结算路径和 Agent 可见消息核验。

**C 当前实现仍有待确认的设计差异：** 原 `arm-standard` 隐藏全部 DAG 工具，而 B 保留 DAG 建图/记录；C 禁用独立 `ts_guess.verify` / strict 接口，但 `ts_prepare` / `ts_resume` / `ts_inspect` 流程仍包含科学判定与 `verified` 结果。此次先同步共同基线和修正真实启动 mode，不在未明确授权时扩大科学功能移除。是否保留计算/原始数值、同时移除自动科学判定与独立校验接口，及 DAG 工具应否与 B 对齐，仍待设计确认。**在此差异消除或明确重定义对比前，不能把当前 B/C 差别称为纯“科学校验工具”效应。**

三条主要对比：

1. **A 对 B：强制干预包的影响。** 观察强制监督和科学结算约束是否减少假成功、增加恢复机会，以及引入多少成本。它不是对 DAG 或 Supervisor 某一独立因素的纯消融，不能据此单独归因。
2. **B 对 C：可调用科学校验工具的影响。** 在都没有上述强制干预的条件下，观察 Agent 是否主动验证、是否识别错误，以及工具可用性如何改变交付。成立前提是两组除这套工具及必要暴露说明外确实一致。
3. **A 对 D：错误诊断引导的影响。** 在规则、工具和拦截能力不变的条件下，观察更丰富的错误解释是否改善纠错、减少打转，或改变成本。两组必须从任务起点独立运行，不共享中途轨迹。

四组共有的化学算法能力不能由这三个对比独立估计效应大小。论文仍需通过真实计算证据和代表性任务讲清这些能力做成了什么，但不将其冒充为已完成的逐算法因果归因。

### D 组的修改边界与残余引导

D 只改变呈现给 Agent 的错误解释长度与诊断指导量，不改变：

- 错误类别、错误码或结构化状态；
- 成败判定、科学阈值、Supervisor 决策与实际拦截；
- 工具可用性、入参 schema、正常成功输出与科学证据；
- partial 的判定、允许范围、交付含义及独立评分。

应保留足以识别失败对象和失败类别的稳定简短信息，删除额外原因展开、纠错步骤和长篇建议；不能把失败伪装成成功、隐藏类别，或将结构化证据字段一并截断。本次映射位于 D 分支 `cloudra/runtime_v2/brief_errors.py`；覆盖范围与残余渠道见该分支 `docs/benchmark/BRIEF_ERROR_ABLATION.md`。

原始错误解释留在既有数据库/事件审计记录中；普通模型回包、JS guest、固定通知、子任务回传及工作区结构化导出不能主动把完整解释重新送回。此项只消融诊断解释，不剥夺四组共同拥有的 Gaussian/ORCA 原始日志、科学数值与正常计算输出。

**隔离限制：** 当前 shell 并非操作系统级文件隔离，移到工作区外的审计数据不能据此宣称绝对不可读；本分支不为消融新增权限或沙箱体系。P0 检查所有正常反馈通道并记录残余可读路径，Pilot 记录是否实际发生完整诊断回流。若发生，应披露并在正式运行前冻结处理/敏感性分析规则，不能把存在回流的运行包装成完全盲化的 A/D 比较。

**混合字段保留：** `ts_guess` 的 `checks` / `verdicts` 等文本会把虚频、距离、能量、几何路径等测量和诊断建议放在同一字符串。为不改变原始科学证据，本次保留这些混合字段，只缩明确的结构化错误和诊断反馈；不临时重构化学输出 schema。因此 D 是“较简略的错误反馈”，不是“全部引导归零”。报告须列明这些残余渠道，不能据此估计完全删除错误指导的效应。

## 三、公平性与运行纪律

### 3.1 统一输入与条件

- 同一冻结题库与题目版本、方法政策、计算环境、工具后端、知识源和独立评估器；每个任务四组配对比较。
- 使用同一模型及版本、推理设置和预算规则。模型、预算类型与上限、每题重复次数尚未决定，不沿用旧计划数字；真实付费调用需在配置与费用范围确认后启动。
- 固定与处理条件无关的提示和正常输出；工具移除、Supervisor 移除及错误解释缩减产生的必要提示差异单独登记，不暗中加入替代性指导。
- 每次运行使用独立干净的工作区、会话与账本。不共享任务记忆、其他组轨迹、已算好的中间答案或人工纠错；若使用公共只读输入或缓存，四组规则一致并披露。
- 记录排队和资源差异，平衡组别运行顺序。基础设施故障的重试与排除规则在看主结果前固定，不只重跑某组失败样本。
- 正式运行冻结版本。若发现影响结论的修复，先标记受影响运行，再按统一规则重跑受影响的配对任务；不将修复前后的轨迹静默拼接。

### 3.2 partial 有位置，但不能冒充完成

给予各组同样的 partial 交付机会：允许交付已有候选、已验证部分、未完成项目和无法支持的结论，但须清楚区分其状态，不要求所有 partial 产物预先在线通过校验。独立离线复核识别其中有证据支持的有效子结果；partial 不得作为完整科学成功计入，也不能因为部分分数较高就升级为 complete。

独立评估器对四组执行同样的证据标准，不把 A/D 的拦截结果当作标准答案，也不把 B/C 的结算成功当作科学正确。C 不提供某项在线校验工具，不意味着离线评估也去掉对应科学检查。

## 四、结果如何判定与报告

同时保留三条轴：**运行与交付状态、独立科学判定、成本**。不要混成一个分数。

| 指标 | 判定与用途 |
| --- | --- |
| 独立科学成功 | 按冻结任务契约及 Gold / 方法边界判定，计算证据完整且结论成立；要求正确拒答或不可达判断的题目，依相应契约审查，不要求补造不存在的证据。 |
| 假成功 | Agent 声称 complete / 科学成立，但独立审计不支持。分别报告每次尝试的发生率，以及已声称完成样本中的比例；同时保留其声明与反证。 |
| 有效 partial | 尚未满足完整契约，但交付了经独立核验的有效子结果，并诚实标明缺口。报告数量、覆盖和缺失类型，不并入完整成功率。 |
| 正确拒答与错误拒答 | 区分合理的科学否定、方法边界说明、因预算未完成和无依据放弃；按题目要求报告，不用一项笼统 abstain 掩盖区别。 |
| 连续评测分数 | 保留图、物理自洽、准确性及综合分的组成，便于描述部分进展。`weighted = 0.9` 是连续加权分数，不是“90% 科学成功率”。 |
| 成本与稳定性 | 计算作业、工具调用、模型调用/token、墙钟与计算资源耗时；具备可靠账单时再报告费用。实际重复次数确定后报告逐题一致性和不确定性。 |

明确分母：所有计划任务、实际启动任务、成功交付任务、可独立评估任务分别有多少。主报告不能只给可评分样本的高分而隐藏运行失败。

特别处理两类现有风险：

- **原生日志 fallback 已存在。** 图绑定不完整时仍可能由原生计算日志恢复科学证据；不能将“没绑定”直接等同于“没计算”或科学零分。它能恢复多少、适用什么条件，需要用当前实现与样本核验。在线交付缺陷与离线可验证证据分别记录。
- **`undelivered` 不是科学零分的同义词。** 它首先是交付状态。原始产物可能存在、可能不足，也可能无法评估，须进入同一审计流程。未能交付仍是系统层面的失败或缺口，但不能凭该标签断言化学计算错误。

统计以任务配对为基本单位，预先选定主指标与主要对比。重复运行不伪装为新增独立题目；报告逐题结果、任务类别分层和适当的不确定性。具体显著性分析与重复数在预算确定后定稿，不先承诺某种效应或显著性。

## 五、用任务和轨迹解释结果

### 5.1 Benchmark 任务分类

正式题库的规模、类别和版本以冻结清单为准，不照搬历史计划。除现有难度标签外，按可检查的任务特征分层，例如单步闭环、竞争路径、多步证据衔接、构象与立体敏感性、方法边界/不可达判断。分类在看主结果前确定，避免根据输赢重新拼组。

“多软结合体系表现不足”目前只是用户的非正式观察，尚未得到清洁重测支持。可将其作为待检验的问题，先把这个类别对应的具体体系与特征说清楚，再检查样本；不得提前写成系统缺陷、算法失效结论或结果章节。

### 5.2 轨迹记录与失败恢复

每条代表性轨迹串起以下问题：

1. Agent 提出了哪些机理假设，如何建立或修改 DAG？
2. 选择了什么化学工具，生成了哪些可追溯的真实计算？
3. 哪些主张已有证据，哪些仍只是猜测或阶段未完成？
4. 失败最先由谁发现：计算后端、工具校验、DAG 契约、Supervisor，还是离线评估器？在线是否实际阻止结算？
5. Agent 收到了什么反馈，采取了什么恢复动作，是否产生新的有效证据，还是重复无效调用？
6. 最后是完整成功、有效 partial、合理否定，还是假成功/无法评价？

行为分析优先使用可审计事件：主动校验、首次错误后恢复、重复同类失败、无证据推进、过早结算、预算耗尽及结论修正。定义清楚“恢复”所需的独立证据，不能把工具返回正常或 Agent 自称解决当作恢复成功。

### 5.3 语义空间分析的边界

可以用嵌入与聚类辅助浏览任务、错误解释或工具调用轨迹，寻找值得回看的行为类型，并回到原始事件和计算证据验证。嵌入结构只描述选定表示下的相似性，不能等同于模型内部机制，也不能据此宣称发现了模型的真实推理过程。四组对比是主要证据，语义空间解释属于补充分析。

### P1：小规模四组通跑

在费用与运行配置获确认后，选取覆盖不同工作流的少量代表任务，四组从头独立运行。目的是检验能否完整经历启动、工具计算、科学失败处理、partial/结算、产物收集与独立评分，不是提前寻找显著结果。

先检查是否卡住、是否标签错位、是否证据丢失、预算是否可比、D 是否仍含完整诊断。若需调整实现或运行规则，冻结新版本后统一重跑受影响样例。Pilot 与正式结果分开标记，不事后择优混入。

### P2：冻结后跑全题集

以 P0/P1 通过的版本和统一规则完成四组全题集，保留所有运行与失败；按预定策略补足重复。以完整结果矩阵为依据再决定是否需要少量针对性的追加实验，不先扩张到逐算法全量消融。

阶段产物是四组运行清单、完整性审计、逐题指标、分层汇总、成本比较和代表性轨迹。只有这些齐全，才开始把“研究假设”改写为论文结果。

## 七、论文组织与可选真实案例

建议正文组织：研究问题与系统主张 → 以具体任务贯穿系统工作链 → 化学算法与证据契约 → 四组实验及公平性 → 独立科学结果与成本 → 轨迹恢复/失败分析 → 适用范围与局限。

代表案例不能只根据好看挑选，应覆盖关键任务类型以及成功、partial、失败，说明为何有代表性。可选加入一个尚未发表的真实机理问题，展示系统在实际研究中的用途；它不是本轮四组通跑的前置条件，须先确认数据使用范围、参考验证方式与可公开内容。不能仅凭“未发表”就宣称没有训练污染，也不能让个案替代 Benchmark。

## 八、开跑前只需先核验的五个代码点

1. **实际 arm 与配置入口：** 分支、运行参数和记录中的 `mode` 是否一致；各组角色与工具暴露是否符合上表，运行产物能否反查真实 commit 和配置。
2. **Supervisor / 结算调用链：** B/C 究竟关闭了什么、还保留了什么；是否仍有隐含的科学强拦截，或误删了共有的协议/安全检查。保留必要状态记录，不将“无强拦截”扩大为“无任何错误处理”。
3. **科学工具边界：** B/C 的差集是否恰好是拟移除的校验工具，而非计算算法、科学证据输出或评估侧校验；不要凭工具名称猜分类。
4. **D 的错误呈现与审计隔离：** 从错误产生到模型可见输出的完整路径是否都按同一映射处理；嵌套对象、代理转发和文件工具是否泄漏原始解释；状态、判定、拦截、成功输出及 partial 是否逐项不变。
5. **独立评分与证据发现：** 日志 fallback 的当前可达路径和条件、`undelivered` 后的审计入口、partial 与 complete 的分离，是否在四组采用同一套规则。

这些点通过后再定最终运行命令。现阶段不凭旧快照补写新代码事实，不自定新的化学阈值或评分权重，也不把计划文件的落盘当作付费实验已经获准启动。

## 九、运行入口与冻结清单

正式运行使用四个独立 checkout，各自记录 `git rev-parse HEAD`，不能在一个运行工作区中途切分支。共同产品代码基线为 `8c568ca6753ecf2cd40a90a8f0f8b5c8e19dd1d2`；分支同步后的提交还含本计划与各自明确的实验差异。

当前有效 CLI 已核对 `python -m cloudra.benchmark --help`。四组均使用同一入口，不传不存在的 `--mode`、`--model` 或硬预算参数；实际 arm 在对应分支固定。

```bash
# 只查入口，不启动模型或计算
python -m cloudra.benchmark --help

# 无模型空后端探针：只查任务加载/沙箱/结果记录与评分管线，
# 空沙箱得分为0是预期，不能算机理实验或控制流验收。
python -m cloudra.benchmark --backend none \
  --tasks-dir ideapool/tasks/easy --only E1 \
  --data-dir /absolute/path/to/isolated/ARM/probe

# 以下仅是配置及费用获批后的正式运行模板，本计划不授权执行。
python -m cloudra.benchmark --backend runtime_v2 \
  --tasks-dir ideapool/tasks/easy --tasks-dir ideapool/tasks/normal \
  --tasks-dir ideapool/tasks/hard --tasks-dir ideapool/tasks/impossible \
  --data-dir /absolute/path/to/isolated/ARM/run --concurrency 1
```

`ARM` 应分别替换为 A/B/C/D，路径不能共用。模型/provider 从现有配置槽位读取并进入 provenance；API pool 如使用，四组策略一致，但任何提交、轨迹或公开配置清单不得包含凭据。

**预算不是已实现的保证：** 当前 CLI 无任务总费用/计算资源硬上限参数，不能仅凭相同命令声称预算公平。正式开跑前须确定模型、可用金额/资源、单题停止规则及其可靠执行方式；在此之前只做无成本工程测试，不自行启动真实模型或远端量化作业。

冻结清单至少包括：四组完整 SHA、共同产品基线、任务清单/哈希、模型与推理设置、有效 arm/角色/工具清单、预算与重复规则、评估器 SHA、输入/输出目录及人工介入记录。当前 GitHub CI 只响应 `master` 推送和面向 `master` 的 PR，实验分支推送本身不会自动运行该 CI，不能把“未触发”写成通过。
