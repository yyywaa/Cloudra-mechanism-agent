# TS 取种与初期诊断

围绕目标反应的实际结构变化选择种子，结合来源计算和优化轨迹判断下一步。扫描峰只是候选；TS 的成立依赖后续无约束优化、频率与连通性证据。方法、基组、模型与热化学方案沿用当前项目要求。

## 禁止脚本插值造种子

**禁止自行编写或运行插值脚本，把两端结构的坐标取平均，或做笛卡尔、内坐标插值来生成 TS 种子。** 不得把“两个极小值的中间结构”当作过渡态初猜，也不得通过“先脚本插值、再做一次优化”绕过这条要求。对齐端点、消除碰撞或换用几何库不改变这条禁令。

坐标中点、手工拼帧和约束扫描峰都不能直接作为已验证 TS 或能垒证据。已有种子应能追溯到具体结构与来源计算。

## 取种前先读结构

- 明确要解释的成键、断键、质子移动或构象变化；从真实结构确定目标坐标和可能耦合的自由度。
- 用 `internal_coordinates` 查看实际原子编号、目标坐标与异常接触。原子对应应来自具体结构，不能从文件名或另一个项目搬用。
- 比较端点或候选时检查原子对应、构型与化学身份；必要时结合对齐后的几何差异和相关内坐标，不能只凭一个 RMSD 数值判为同一极小值。

## 从松弛扫描选择候选

1. 使用结构化扫描工具声明坐标、范围和约束。连续扫描从前一点的收敛末帧续接，让其他自由度弛豫；核对实际坐标，确认约束确实生效。
2. 结合能量和逐帧几何检查剖面。只有同一计算层次、同一连续分支的点才能直接比较；构象或连接发生跳变时，先区分分支，不能把不同分支的低能点拼成一条反应路径。
3. 从连续剖面的峰附近选择种子，保留对应几何与原始日志。峰位在边界、剖面单调或出现跳变时，先检查扫描范围、方向和耦合运动，再决定如何补充搜索；不要直接把当前最高点称为鞍点。
4. 用新的无约束 TS 精修检验候选，去掉探索扫描遗留的冻结与扫描设置。约束优化收敛只说明该约束条件下的计算收敛。

已有路径候选的取法与引擎配方按需查阅 `dft-calculation` 的 `ts-search-playbook.md`；本 skill 的脚本插值禁令仍然适用。

## 首步诊断

从首个优化步开始检查搜索是否沿着目标反应推进。以下观察用于诊断，本 skill 不设通用自动停算阈值。

| 观察项 | 要判断的问题 |
| --- | --- |
| 初始 Hessian 的负曲率与模式 | 当前几何附近的曲率与实际跟踪的运动是否一致 |
| 所跟踪模式的成分 | 运动是否对应目标反应，还是无关的转动或构象变化 |
| 目标坐标与整体几何的变化 | 是否偏离预期路径、出现异常接触或滑向其他构象 |
| 预测能量、实际能量与力的趋势 | 是否支持当前搜索方向，是否与观察到的结构变化相符 |

结合已有优化轨迹和种子来源，决定继续观察、调整搜索还是停止换种，并说明理由。初始负本征值不为 1、某一步角度变化较大或一次预测能量下降，都不单独触发停算。首步诊断不能代替最终的频率与连通性验收。

Gaussian 日志中的 `D<n>` 是引擎内坐标表的序号；应按原子元组找到目标二面角，核对角度单位，不照搬其他作业的 `D<n>`。

## 在同一 TS 流程中换种

- 同一路径只调用一次 `ts_prepare`；正常完成的作业由系统自动推进。
- 用 `ts_inspect(run_id)` 读取状态、实际原子表、失败信息和可用结果；不用空的 `ts_resume` 调用轮询。
- 修改现有输入使用 `ts_resume(run_id, changes, reason)`。更换已有候选时，`changes.guess` 选择 `provided`，提供候选 XYZ 与来源证据；不要复制内部映射、版本号或哈希。
- 需要停止时调用 `ts_stop(run_id, reason)`，由计算账本和执行端处理取消；待运行中和取消中的作业收尾后再修订。不得自行 kill 计算进程，也不因日志暂时静默认定作业死亡。

更换候选的调用形状如下；运行编号和文件路径须替换为当前运行的真实值。XYZ 必须使用当前绑定反应物的完整原子顺序。

```json
{
  "run_id": "ts_0001",
  "changes": {
    "guess": {
      "kind": "provided",
      "xyz_path": "/workspace/candidate.xyz",
      "evidence_refs": ["/workspace/scan.log"]
    }
  },
  "reason": "根据已检查的连续扫描峰帧更换候选"
}
```

这只是输入修订，不代表科学验证通过。独立提交作业时使用当前的专门输入生成与提交工具，保留同样的科学证据要求。

## 先分清失败原因

| 观察 | 下一步 |
| --- | --- |
| 输入语法错误、文件路径错误、声明被拒 | 修正被点名的输入或文件；不能当作反应不可行 |
| 进程被外部终止、内存不足或环境报错 | 根据执行端诊断处理资源与环境，不改写成化学失败 |
| 精修滑回极小值或跟错运动 | 对照几何、模式和力的变化，重新检查种子、构象与路径假设 |
| 扫描不连续或约束漂移 | 检查真实逐帧坐标与构象分支，确认扫描实际执行了什么 |

优先使用专用解析工具读取几何、频率和作业诊断。输入格式问题按需查阅当前引擎的 `gaussian-inputs.md` 或 `orca-inputs.md`，不为每个新项目重复编写日志或几何解析脚本。

## 从候选到验证结果

- **精修收敛**：依据引擎原生优化收敛信息与最终几何；退出码为零或正常终止标记本身不能证明找到鞍点。
- **频率与模式**：在要求的计算层次验证恰一个虚频，且运动对应所声明的反应变化。成键、断键、质子转移和转动应检查各自相关的运动，不能套用另一个体系的模式编号或占比阈值。
- **双向连通性**：保留短 IRC 的方向证据与两端结构，核对其与目标端点的关系；两端无约束优化、零虚频及身份验证按既有验收要求完成。短 IRC 的方向证明与完整路径收敛应分别描述。
- **能量与热化学**：只从符合项目要求且可比的计算中提取最终数值。没有完成的计算或连通性检查应明确列出，不用扫描峰高代替已验证能垒。

交接候选来源、所检验的反应变化、当前诊断、下一步理由及尚缺的验证证据，并提供原始日志与对应几何路径。已获得频率证据和已经完成全部验证应分别说明。
